# goals — プロジェクトの目的と完成形

作成日時: 2026-09-21 17:59
更新日時: 2026-09-21 17:59

## 目的

本(小説・技術書)のスクリーンショットを固めた zip を取り込み、ローカル LLM で本文を
テキスト化・構造化して、読書と内容の理解を助けるブックリーダーを作る。

manga-viewer(漫画ビューワ + ローカル LLM 解析)を土台に作り替える。

## 完成形

1. **取り込み** — どこにある zip / cbz / pdf でも「本を取り込む」で管理ルートに保存する。
   1 冊 1 フォルダで、元ファイル・本文・図・要約をまとめて持つ。
2. **本文化** — 各ページを OCR / Vision LLM で Markdown に書き起こす。
   - 図・表・写真は切り抜いて画像にし、本文の該当位置に挿入する。
   - ヘッダー・ページ番号などのノイズを除き、ページをまたぐ段落をつなぐ。
   - 縦書き(日本語の小説)とルビに対応する。
3. **構造化** — 目次・見出しから章を検出し、章ごと・本全体の要約を作る。
   章の区切りは人が直せる。
4. **読書** — 原本(画像)表示とテキスト表示を切り替えて読める。縦書きの本は縦書きで表示する。
   しおり・読書位置・検索がある。
5. **チャット** — 本の内容についてローカル LLM と話せる。章の要約と、質問に関係する本文を
   検索して文脈にする。小説では今読んでいる位置より先を文脈に入れない(ネタバレ防止)。

## 重視する価値

- **すべてローカルで完結する** — 画像・本文・推論を外部に送らない。
- **データは人が読める形で残す** — 本文は Markdown、メタデータは JSON。本フォルダだけで
  中身が分かり、他のツール(Obsidian / VS Code など)でも開ける。DB は作り直せる索引に留める。
- **元データを壊さない** — 取り込んだ元アーカイブは変更しない。生成物はいつでも作り直せる。
- **自動処理の誤りを人が直せる** — OCR 結果や章の区切りは原本と見比べて修正できる。
- **長い処理は止めても再開できる** — 取り込み後の OCR・要約はキューで処理し、途中から続けられる。

## 対象外(当面)

- 印刷物をスキャンした画像の高度な補正(傾き・歪み補正など)
- EPUB / テキストファイルなど、画像以外の本の取り込み
- 複数端末での同期
