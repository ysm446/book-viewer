# book-viewer

本(小説・技術書)のスクリーンショットを固めた zip / cbz / pdf を取り込み、ローカル LLM で
本文をテキスト(Markdown)化・構造化して、読みながら内容についてチャットできるデスクトップの
ブックリーダー。画像も推論もすべてローカルで完結する。

漫画ビューワ(manga-viewer)を土台に作り替えている途中。

## 目指す形

1. **取り込み** — どこにある zip でも「本を取り込む」で管理ルートに保存する(1 冊 1 フォルダ)
2. **本文化** — 各ページを OCR / Vision LLM で Markdown に書き起こす。図は切り抜いて本文に挿入する。
   縦書き・ルビにも対応する
3. **構造化** — 章を検出し、章ごと・本全体の要約を作る
4. **読書** — 原本(画像)表示とテキスト表示を切り替えて読む。縦書きの本は縦書きで表示する
5. **チャット** — 章の要約と関連する本文を文脈に、本の内容についてローカル LLM と話す。
   小説では今読んでいる位置より先を文脈に入れない(ネタバレ防止)

## 使い方

1. 起動したら、一覧上部の管理ルート欄から本を保存するフォルダを選ぶ
2. 一覧上部の `＋` を押すか、ウィンドウへ zip / cbz / pdf をドラッグ&ドロップする(複数可)
3. 取り込みダイアログで書名・著者・書字方向(横書き / 縦書き)を確認し、
   元ファイルを「コピーして残す」か「移動する」かを選んで取り込む
4. 一覧から本を選んで読む
5. 本文で読むには、リーダー上部の「テキスト」に切り替えて「残り ○ ページを文字起こし」を押す
   (一覧の本のメニューからも実行できる)。LLM の読み込みは不要

- 書名の初期値はファイル名から作る。先頭の日時(例: `2026-09-20_1847_`)は取り除く
- 同じ内容の本が既にあれば警告し、初期状態で取り込み対象から外す
- 管理ルート内に置いたままの未取り込みファイルがあると一覧上部に案内が出て、まとめて取り込める
  (この場合は「移動する」が初期値)

## ライブラリの構成

取り込んだ本は管理ルート直下に 1 冊 1 フォルダで保存する。本フォルダが正本で、
`library.db` は一覧・検索・読書位置などの索引。

```
<管理ルート>/
├─ .book-viewer/
│   ├─ library.db            索引・検索・読書位置・しおり
│   └─ thumbnails/           サムネイルキャッシュ
└─ <書名>/
    ├─ book.json             ID・書名・著者・書字方向・元ファイル名
    ├─ source/original.zip   取り込んだ元アーカイブ(変更しない)
    ├─ pages/0001.md …       文字起こしした本文(1 ページ 1 ファイルの Markdown)
    └─ figures/p0001-1.png … 本文から切り抜いた図(Markdown から ../figures/… で参照)
```

- 本フォルダ名を変えても、`book.json` の ID で同じ本として扱われる
- 今後、要約(`summaries/`)も本フォルダに置く
- 対応アーカイブ: `.zip` / `.cbz` / `.pdf`
- アーカイブ内の対応画像: `.jpg` / `.jpeg` / `.png` / `.webp` / `.gif` / `.bmp`

## 主な機能

### ライブラリ
- 本の取り込み(ファイル選択 / ドラッグ&ドロップ / 管理ルート内の未取り込みファイル)
- サムネイル付き一覧、タイトル・あらすじ・ページ内容の横断検索(FTS5)
- 既読状態・タグでの絞り込み、並び替え(タイトル / 追加順 / 最近開いた順 / 手動ドラッグ)
- 本ごとのメニューから解析実行・名前の変更(本フォルダ名も追従)・削除(本フォルダをごみ箱へ移動)
- 管理ルートは最近開いた履歴から選び直せる。前回のルートと最後に開いていた本は起動時に復元される

### リーダー
- 画像(スクリーンショット)表示とテキスト(文字起こしした本文)表示の切り替え。
  テキスト表示は Markdown を組版し、縦書きの本は縦書きで表示する(ホイールで読み進められる)
- テキスト表示から、未処理ページの文字起こし・表示中ページのやり直しができる。進み具合も表示する
- 書字方向(横書き / 縦書き)は「表示」から本ごとに変えられる
- 見開き / 単ページ表示、右開き・左開き(本ごとに上書き可)、見開きペアのずらし
- 横長ページの単独表示、表紙の単独表示、ページめくりエフェクト
- 読書位置の保存(続きから読める)、しおり(サムネイル付きバー)、ページスクラバー
- 上部メニューから しおり / タグ / 解析・あらすじ / 表示設定 をパネルで開閉
- スクリーンショット(`F12` = ウィンドウ、`F9` = 表示中のページ画像)。
  保存先は `<管理ルート>/screenshot/`。保存すると右下に通知が出て、クリックで保存先を開ける

### 文字起こし
- 既定は YomiToku(日本語の文書 OCR + レイアウト解析)。1 ページ 1 秒未満で、縦書き・読み順・
  見出し・図の領域を扱える。電子書籍リーダーの画面の書名・ページ表示は除き、ルビは今は落とす
- 図・表は切り抜いて本文の位置に挿入し、キャプションを添える
- 設定 > AI 解析 で Vision LLM による文字起こしにも切り替えられる(遅く、言い換えが混ざることがある。
  比較は [scripts/ocr-compare/](scripts/ocr-compare/README.md))

### 本のチャット
- リーダー上部の「チャット」で、本の内容についてローカル LLM と会話できる(モデルの読み込みが必要)
- 文脈には、文字起こし済みの本文のうち「いま開いているページまで」を、近いページから
  コンテキスト長の半分ほどまで渡す。先のページは渡さない(ネタバレ防止)
- 答えには根拠のページ(p.○)を添え、本文に無いことは推測・一般知識と断って答える
- 「このページについて」で現在ページ中心に答える。「画像」で現在ページの画像も送る(Vision モデルのみ)
- 質問候補は定番の質問に加え、今のページ付近の本文から作った質問を混ぜる

### ローカル LLM(llama.cpp)
- llama.cpp ビルドの取得、モデルのロード / アンロードをアプリ内から行える
- 解析はキューで直列実行。ステータスバーに進捗バー・経過時間・中止 / 待機取消を表示
- ステータスバーで CPU / RAM / GPU / VRAM の使用状況を確認できる

土台から引き継いだ漫画向けの解析(M2 以降で本向けの処理に置き換える予定):
- Vision モデルでページを解析し、あらすじ・タグを自動生成。ページ単位の解析結果をオーバーレイ表示

## キーボード操作(リーダー)

| キー | 動作 |
| --- | --- |
| `←` / `→` | ページ送り(読み進め方向に追従) |
| `↑` / `↓` | 前ページ / 次ページ(テキスト表示では本文のスクロール) |
| `S` | 見開きペアをずらす(見開き表示時) |
| `B` | 現在ページのしおりを付け外し |
| `F9` | 表示中のページ画像を保存(見開きなら 2 枚) |
| `F12` | ウィンドウのコンテンツ領域をキャプチャして保存 |
| `Esc` | 一覧へ戻る |

`F9` はアーカイブ内の画像を無加工のまま書き出すため、劣化せず UI も写らない
(PDF は表示と同じくラスタライズした JPEG)。`F12` は画面の見た目をそのまま PNG で残す。

## 設定

設定モーダルは 4 タブ構成。

- **表示** — 表示モード(見開き / 単ページ)、横長ページの単独表示、表紙の単独表示、
  ページめくりエフェクト、既定の読み進め方向
- **ランタイム** — llama.cpp ビルドのダウンロード / 選択、`llama-server` パスの手動指定、
  モデルフォルダ(GGUF の置き場)、コンテキスト長、思考モード(reasoning)
- **AI 解析** — 文字起こしのエンジン(YomiToku / Vision LLM)、解析する代表ページ数、システムプロンプト、前ページの文脈参照(参照ページ数)、
  物語のまとめを文脈に使う(更新間隔)
- **チャット** — システムプロンプト(本向けの既定に戻せる)、本文から質問候補を作る

設定は `data/settings.json` に保存される(git 管理外)。

## 技術スタック

- フロント: Electron + React + TypeScript(electron-vite / Vite)
- バックエンド: Python(FastAPI / uvicorn)。Electron が venv の Python を自動起動
- ローカル LLM: llama.cpp(`vendor/llama_cpp/versions/<version>/llama-server` を起動して HTTP)
- 画像: Pillow(サムネイル・ページ配信)、PDF は pypdfium2 でラスタライズ
- 文字起こし: YomiToku(torch。モデルは CC BY-NC-SA 4.0 の非商用ライセンス)
- データ: 本ごとのフォルダ(正本)+ 管理ルートごとの SQLite 索引

## セットアップ

前提: Windows + Node.js 18 以降(Electron 33 の要件)と Python 3(`py -3` が使えること。
開発環境は 3.13)。

```bash
# 依存の導入
npm install
cd backend && py -3 -m venv .venv && ./.venv/Scripts/python.exe -m pip install -r requirements.txt

# GPU で文字起こし(YomiToku)を動かす場合は、CUDA 版 torch を先に入れる(詳細は requirements.txt)
#   ./.venv/Scripts/python.exe -m pip install --index-url https://download.pytorch.org/whl/cu128 torch torchvision

# 起動(Electron が venv の Python backend を自動起動する)
npm run dev
```

LLM を使う場合は、`models/` に GGUF モデル(Vision 対応 + mmproj)を配置し、
アプリ内のモデル選択バーからロードする。別の場所にまとめてある場合は、
設定 > ランタイム > モデルフォルダ でそのフォルダを指定する(空なら `models/`)。
llama.cpp のビルドは設定画面からダウンロードできる。

## 開発

```bash
npm run typecheck   # 型チェック
npm run build       # ビルド

# バックエンド単体(デバッグ用)
cd backend && ./.venv/Scripts/python.exe -m uvicorn app.main:app --port 8771
```

```
src/main/        Electron メインプロセス(ウィンドウ、Python 起動・死活監視)
src/preload/     contextBridge による IPC 公開
src/renderer/    React UI(一覧 / リーダー / 取り込みダイアログ)
backend/app/     FastAPI(library / scanner / archive / db / analysis / llm / routers)
models/          GGUF モデル(git 管理外)
vendor/          llama.cpp 等の外部バイナリ(git 管理外)
data/            実行時生成物・設定(git 管理外)
```
